# 音乐体验与童趣界面升级

## Goal

在保持浙江省人音版小学教材主线、离线单文件能力和现有乐器/游戏资产的前提下，把学生端升级为低门槛、可感知、可创作的“音乐探索游乐园”。学生进入后应能在十秒内听见声音、两次点击内开始互动，并留下一个音乐发现或小作品。

## Requirements

- 建立统一的“听一听 → 找一找 → 动一动 → 玩一玩 → 创一创 → 说一说”音乐体验闭环；每次体验默认 1—5 分钟，按年级调整复杂度。
- 新增三个可复用的 code-native 互动类型：声音侦探（A/B 听辨）、节奏精灵（点击/跟拍/回声）、音乐画布（颜色/线条/动作表达）。默认不要求麦克风，麦克风只作为可选增强。
- 将现有教材主题和浙江拓展主题映射到互动体验；低年级偏模仿与身体律动，中年级偏比较与规律，高年级偏配器、结构和审美表达。
- 保留首页“探索卡片”和“本次进度”，但把首页主行动收拢为“今日音乐探险”；不增加排行榜、虚拟货币、班级竞争或大量徽章。
- 学生导航收拢为“今日、探索、玩乐、我的”四个主入口；原有课程、素材、乐器和游戏仍可从对应场馆或首页进入。
- 全站应用“音乐手作乐园”视觉语言：暖色纸片感、圆润几何、清晰层级、适量弹性动效；同一系统适配 1—6 年级，不做幼儿化独立皮肤。
- 本轮教学展示优化只验收 1280×720 电脑端投屏、键盘访问、减少动画和关闭音效；手机端保持现状，不纳入本轮修改范围；不引入远程字体、远程图片或必须联网的运行时依赖。
- 根目录单文件通过现有 Vite single-file 构建同步更新。
- 教学展示视口：在 1280×720 电脑端投屏中，主要页面默认不依赖外层滚动；长内容必须通过分页、步骤、标签页或场景切换继续访问。
- 展示页导航：分页控件需要显示当前页、总页数，并支持鼠标/触控、键盘方向键和减少动画偏好。
- 列表可达性：素材、主题、名册等长列表不得用隐藏的内部滚动容器承载主要内容，应提供明确的列表分页或分步入口。

## Acceptance Criteria

- [ ] 学生从首页进入“今日音乐探险”不超过两次点击，并在首屏看到保留的探索卡片。
- [ ] 三种互动类型均能产生真实可见状态变化和真实本地音频反馈；无音频权限时仍可用触控路径完成。
- [ ] 同一主题可根据 1—2、3—4、5—6 年级显示不同提示和难度，不复制三套页面。
- [ ] 学生可在体验结束时保存一条“我的音乐发现”，并按当前学生隔离读取。
- [ ] 学生端主导航最多四个一级入口；教师档案/观察入口继续仅在教师模式显示。
- [ ] 首页首屏只保留一个主要 CTA、探索卡片、本次进度和轻量发现入口，不恢复多 KPI 堆叠。
- [ ] 1280×720 电脑端无横向溢出，主要操作目标清晰可点，`prefers-reduced-motion` 生效；手机端不回归、不主动改版。
- [ ] `npm test`、`npm run lint`、`npx tsc -b`、`npm run build` 全部通过；生成的单文件与 `dist/index.html` 内容一致。
- [ ] 每个实施阶段均有独立 Git 提交，工作树最终干净且不推送远程。
- [ ] 主要路由在 1280×720 首屏无外层纵向滚动，长内容可通过页面切换完整到达。

## Notes

- 视觉资产优先使用现有 emoji、CSS 和 SVG；当前环境没有可调用的内置 Image Gen 工具，故不新增必须由位图资产承载的品牌或游戏角色。
- 现有 `audioEngine`、`uiSounds`、`explorationLoop`、`discoveries`、`theoryCatalog` 和乐器页面作为复用基础，不重复实现已有音频/记录逻辑。
- 这是一次跨页面的体验升级，先按可独立验收的阶段实施，再逐步替换旧入口；不做无关的底层重构。
