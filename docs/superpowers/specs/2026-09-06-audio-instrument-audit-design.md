# 音频、乐器与桌面端功能审计设计

## 背景

当前应用已经包含音乐探索馆、互动课堂、森林乐器大冒险、旧版小游戏、作品与素材库及多个乐器练习页。本轮目标不是删减已有学习路径，而是把所有“听”的入口统一到可靠的音频资源与可停止的播放生命周期上，并对电脑端单文件 `乐动课堂.html` 做一次真实可用性审计。

## 目标

1. 音乐探索馆的木鱼、碰钟、钢琴试听必须分别产生可辨识的声音；真实音频优先，素材不可用时才使用明确的合成音色兜底。
2. 森林乐器大冒险的“听听我的节奏”必须按学生编排的顺序完整回放，休止符保持安静，重复点击和离开页面不能叠加或残留播放。
3. 参考音频在开发页面和直接双击打开的单文件中都能加载，不依赖服务器根路径。
4. 左侧乐器栏覆盖应用实际使用的乐器，并且每个入口都有真实可操作的试听内容。
5. 对电脑端主要页面和小游戏的音频按钮、进入/返回、重试、筛选与作品试听做定向回归检查，修复本轮发现的功能性问题。

## 非目标

- 不重做移动端和平板端布局或交互。
- 不删除阶段一至四、旧小游戏、作品地图/素材库合并后的功能、森林游戏或现有课堂导航。
- 不把单纯的知识文案改成新的课程体系；本轮聚焦音频行为、资源可靠性和桌面端功能闭环。

## 设计

### 1. 统一资源层

应用内可被单文件引用的音频统一从 `src/music` 导入。`referenceAssets.ts` 暴露稳定的资源对象，而不是拼接 `/reference-courseware/...` 的运行时绝对路径。Vite 的 assets inline 配置会把这些导入的音频转成 data URL，因而 `乐动课堂.html` 在 `file://` 下也可播放。

资源层同时描述资源对应的 `InstrumentId`。真实参考音频和 Tone 合成音色不是互相竞争的两套状态：调用方先尝试真实资源，加载或播放失败时才回退到指定的合成 patch/打击乐音色，并向界面提供可理解的播放状态。

### 2. 播放生命周期

所有新增的连续播放都遵循同一规则：新播放开始前停止旧播放；组件卸载、路由切换和重新提交时清理 timer、audio element 与 Tone transport；空输入不启动播放；播放状态明确显示“正在播放/播放完成”。这样可以避免重复点击产生重叠声音，也避免切页后声音继续响。

### 3. 音乐探索馆试听

三个候选保留现有 A/B 选择、文化线索和听感反馈流程，但试听数据增加对应资源与乐器 ID：木鱼使用木鱼资源、碰钟使用碰钟资源、钢琴使用钢琴采样或钢琴 patch。试听按钮只播放当前候选，不再全部走 `audioEngine` 默认钢琴 patch。

### 4. 节奏回放

节奏卡仍可单卡试听；“听听我的节奏”播放整条 pattern。每个节奏单元使用统一时值，`X`、`XX` 触发打击声，`—` 只推进时间不发声。回放期间按钮禁用或显示进行中，提交记录与完成提示在回放完成后更新，避免学生以为点击无效。

### 5. 乐器导航

保留钢琴、架子鼓、竖笛、木琴，并增加当前应用实际出现的木鱼、响板、碰钟、锣、鼓、钹、琵琶、二胡、竹笛、小提琴、贝斯、马林巴、八音盒、管风琴/电子琴、合成器、拨弦等入口。乐器入口采用共用试听页和数据驱动配置，避免每个乐器复制一套页面逻辑；入口展示名称、听感提示、示范按钮和可选的文化线索。

### 6. 单文件与桌面端

构建后复制 `dist/index.html` 为根目录 `乐动课堂.html`。验收以直接打开 `file:///.../乐动课堂.html` 为准，同时在开发服务器验证资源导入没有破坏 HMR。只检查电脑端视口和桌面交互。

## 验收标准

- 音乐探索馆的木鱼、碰钟、钢琴试听不会共享默认钢琴声音；资源失败时仍能听到不同的兜底音色。
- 森林游戏能完整回放非空节奏；空节奏有提示；重复点击、离开页面后无叠音或残留。
- 单文件中参考音频不再依赖 `/reference-courseware` 根路径，音频元素可加载并播放。
- 左侧每个实际使用乐器均能进入试听页并触发对应声音。
- 现有测试、Lint、TypeScript 构建通过；单文件重新生成且与源码功能同步。
- 电脑端关键页面和旧小游戏的进入、返回、试听、重试等操作完成定向冒烟检查。
