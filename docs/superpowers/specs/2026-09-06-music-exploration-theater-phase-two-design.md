# 音乐探索剧场第二阶段：桌面端听觉工具与作品地图设计规格

## 1. 文档状态

- 状态：待用户审阅
- 日期：2026-09-06
- 适用产品：乐动课堂（浙江省小学 1—6 年级音乐课堂）
- 目标平台：电脑端桌面布局
- 前置阶段：音乐探索剧场第一阶段、茉莉花探索单元、发现卡和探索会话

本阶段承接第一阶段的主线：

> 先听 → 表达感受 → 找音乐证据 → 音乐线索浮现 → 再听 → 保存发现

本阶段不以迁移旧功能为目标，而是增加能够帮助学生“听见证据”的桌面端工具，并将作品浏览和听觉工具重新组织到欣赏体验中。

## 2. 产品目标

### 2.1 本阶段要解决的问题

第一阶段已经提供了完整的茉莉花探索流程，但学生寻找证据时主要依赖 A/B 试听和文字选项。第二阶段需要让学生能够通过操作、比较和回听更具体地感知：

- 音乐在哪里发生变化。
- 旋律、节奏、力度和音色怎样造成感受。
- 乐器的声音有什么质感和文化联系。
- 身体动作和节奏判断如何帮助理解音乐。
- 背景文化进入后，自己的理解有没有变化。

### 2.2 成功标准

学生完成一个第二阶段样板探索后，应至少能够：

1. 使用一种听觉工具完成主动聆听，而不是只点击答案。
2. 把工具中的观察转化为一个音乐证据。
3. 在再次聆听时回到同一音乐片段验证自己的判断。
4. 在作品地图中按照年级、主题或路径找到探索内容。
5. 在听觉实验室中理解工具与音乐欣赏的关系，而不是把工具当成孤立小游戏。

教师在桌面投屏或电脑端操作时，应能够快速从作品进入探索、从证据工具回到作品，并保留原有课程、理论和挑战入口。

## 3. 平台与范围边界

### 3.1 桌面端优先

本阶段只针对电脑端设计和验收：

- 以宽屏三栏、双栏和工作台布局为主。
- 允许新增横向比较、时间线、工具面板和投屏信息密度。
- 不修改手机底部导航。
- 不修改平板或窄屏专用布局。
- 不新增移动端断点和移动端交互适配。
- 不以移动端不溢出、不换行作为本阶段验收条件。

现有移动端代码保持可编译和基本可用，但不为移动端新增视觉和交互工作。

### 3.2 保留的能力

- React 18、TypeScript、Vite 和单文件构建方式。
- Tone.js / Web Audio 音频能力和现有音频降级策略。
- 现有 `localStorage` 数据模式。
- 第一阶段的 `ExplorationUnit`、`ExplorationSession`、`MusicDiscovery` 和 `ExplorationTheater`。
- 旧理论页面、挑战游戏、乐器页面和教师入口。

### 3.3 不在本阶段实现

- 真实录音素材管理后台。
- 云端账户、课堂实时协作和多人同步。
- 录音上传、语音识别或摄像头动作识别。
- 全量重写所有旧游戏。
- 全量拆分理论百科内容。
- 手机和平板专门设计。
- 第二阶段以外的新作品大规模内容生产。

## 4. 推荐体验结构

### 4.1 桌面端信息架构

学生端的桌面主入口维持四个方向，但重新解释其内容：

| 入口 | 第二阶段定位 | 主动作 |
| --- | --- | --- |
| 今日探索 | 今日推荐作品和继续探索 | 进入探索剧场 |
| 作品地图 | 按作品、教材、器乐和文化主题浏览 | 选择作品并开始探索 |
| 听觉实验室 | 按听觉问题选择工具 | 选择工具并带着问题练习 |
| 我的发现 | 回看感受、证据、工具记录和二次聆听变化 | 再听或回到作品 |

### 4.2 推荐主流程

```text
作品地图
  ↓
选择《茉莉花》
  ↓
音乐探索剧场：先听与表达
  ↓
选择“我想找节奏 / 乐器 / 旋律变化”
  ↓
打开对应听觉工具
  ↓
记录一个可听见的证据
  ↓
回到同一片段再听
  ↓
保存带有工具证据的音乐发现卡
```

工具不能成为脱离作品的终点。每个工具都必须提供“回到作品”“再听原片段”或等价的返回动作。

## 5. 三个新增桌面端听觉工具

本阶段新增工具都以“发现证据”为目标，不以分数和唯一答案为主。

### 5.1 音乐显微镜

#### 目的

帮助学生定位和比较音乐变化，回答：

> “我说音乐变了，具体是哪里变了？”

#### 核心交互

- 显示核心片段的分段时间线或乐句卡。
- 支持 A/B 片段试听并标记当前片段。
- 学生可以点击“更快 / 更慢”“更强 / 更弱”“更连贯 / 更跳跃”等观察标签。
- 学生可以标记“变化发生在这里”。
- 工具生成观察反馈，但不直接判断审美感受对错。
- 提供“回到作品再听”按钮。

#### 茉莉花样板

第一版至少支持“流动旋律”和“跳跃旋律”的比较，并把学生选择转化为可保存的证据，例如“旋律更平稳”“音与音之间走得更近”。

### 5.2 乐器探秘台

#### 目的

帮助学生从声音质感进入器乐欣赏，回答：

> “我听到的声音为什么有这样的颜色？”

#### 核心交互

- 先试听若干声音样本，不先显示标准答案。
- 选择声音质感，如“清脆、柔和、明亮、厚重、颗粒感”。
- 比较两个或三个音色样本。
- 选择可能的乐器或乐器家族。
- 展示简短的演奏方式和文化信息。
- 进入“在作品里再找找这个声音”。

#### 内容边界

第一版可使用现有 Tone.js / 合成音色模拟，不要求录音级真实音色。UI 文案必须明确这是“听辨和比较的声音样本”，避免把合成音色误称为真实录音。

### 5.3 节奏与动作工作台

#### 目的

帮助学生用身体动作和时间感理解节奏，回答：

> “音乐怎样让我想走、跳、摇或停？”

#### 核心交互

- 显示稳定拍和乐句时间线。
- 支持鼠标点击或键盘空格跟随拍点。
- 学生可以选择动作词：走、跳、摇、停、推、拉。
- 可试听重音、停顿和节奏变化。
- 显示观察性反馈，如“你的点击集中在稳定拍附近”。
- 将节奏观察转化为发现卡证据。

#### 评分原则

不把身体表达直接判为错误。若计算准确度，只用于给出“稳定、正在靠近、可以再听”的过程反馈，不作为审美评分。

## 6. 文化换镜

文化信息必须服务于再次聆听，而不是成为背景知识阅读页。

### 6.1 交互顺序

```text
第一次聆听 → 学生表达 → 显示一小段文化信息 → 选择重新关注的声音 → 再听 → 修改或保留理解
```

### 6.2 茉莉花样板

文化信息可以包含江南水乡、民歌传唱、不同地域版本和民乐演奏方式，但每次只显示一到两条与当前听觉证据相关的信息。学生必须有明确的“带着这个线索再听”动作。

### 6.3 数据结果

文化换镜不要求学生回答文化知识题。它只记录：

- 是否打开文化信息。
- 再听后选择保留、增加或改变理解。
- 学生写下的文化联想或音乐变化。

## 7. 数据与组件设计

### 7.1 探索单元扩展

在第一阶段 `ExplorationUnit` 基础上增加可选的桌面工具配置，建议包括：

```ts
interface ExplorationToolReference {
  id: 'microscope' | 'instrument' | 'rhythm'
  stage: 'evidence' | 'concept' | 'relisten'
  title: string
  question: string
  evidenceLabels: string[]
}
```

工具配置是可选的，旧探索单元不需要补齐；没有配置时继续使用第一阶段的 A/B 证据流程。

### 7.2 发现卡扩展

新字段全部可选，旧记录继续可读：

```ts
interface MusicDiscoveryToolNote {
  toolId: 'microscope' | 'instrument' | 'rhythm'
  observation: string
  evidence: string[]
}
```

`MusicDiscovery` 可以增加 `toolNotes?: MusicDiscoveryToolNote[]`，并限制每张发现卡最多保存 3 条工具记录、每条最多 4 条证据标签。

### 7.3 组件边界

建议新增以下纯数据和 UI 边界：

- `src/music/explorationTools.ts`：工具元数据、样板音频序列和观察反馈规则。
- `src/components/MusicMicroscope.tsx`：桌面音乐显微镜。
- `src/components/InstrumentExplorer.tsx`：桌面乐器探秘台。
- `src/components/RhythmMovementLab.tsx`：桌面节奏与动作工作台。
- `src/components/explorationTools.css`：三个工具的桌面端样式。
- `src/pages/WorksMap.tsx` 或在 `CourseCenter.tsx` 内实现作品地图视图。
- `src/pages/AuditoryLab.tsx` 或在 `TrainingCenter.tsx` 内实现听觉实验室视图。

第一版优先采用独立组件和现有路由入口，避免把所有工具逻辑继续堆入 `ExplorationTheater.tsx`。

## 8. 页面改造方向

### 8.1 作品地图

作品地图桌面端至少包含：

- 当前年级和教材范围摘要。
- 作品卡：标题、片段、主路径、可用工具、文化主题。
- 筛选：年级、教材来源、器乐/文化标签、情绪/动作/故事/文化路径。
- 主按钮“开始探索”。
- 次按钮“查看音乐线索”或“打开听觉工具”。
- 没有匹配结果时的引导，不展示与筛选不相关的旧主题。

第一版只需要把茉莉花和现有可映射作品做成可用卡片，不要求一次完成全部曲库迁移。

### 8.2 听觉实验室

听觉实验室桌面端至少包含：

- 三个新增工具卡。
- 每个工具卡的核心问题和适用年级。
- “从一段作品开始”入口。
- “自由练习”入口，允许不绑定作品体验工具。
- 旧挑战中心作为“更多练习”区域保留。

自由练习也必须使用观察性反馈，避免重新变成知识答题首页。

### 8.3 探索剧场接入

探索剧场在证据阶段或概念阶段显示与当前探索单元匹配的工具卡。工具打开后可以：

- 在当前页面内展开桌面工作台；或
- 进入工具路由并携带返回作品和阶段信息。

推荐第一版使用当前页面内展开，避免学生丢失探索上下文；如果组件复杂度过高，再使用带焦点的路由返回。

## 9. 反馈和可访问性

- 工具操作结果使用 `role="status"` 或 `aria-live="polite"` 呈现。
- 颜色不是唯一反馈方式，所有标签同时显示文字。
- 键盘可以完成播放、选择、确认、标记和返回作品。
- 播放按钮必须显示当前状态，重复点击不能叠加旧片段。
- 音频不可用时，工具仍可选择、比较、保存观察。
- 不把主观感受显示为“正确/错误”。
- 桌面端默认采用清晰的左侧工具步骤、中间声音互动、右侧观察记录布局。

## 10. 验收标准

### 自动化验收

- 工具元数据和观察反馈规则有纯函数测试。
- 三个工具分别有核心交互的组件源码契约或行为测试。
- `ExplorationUnit` 可选工具字段不破坏旧单元。
- 旧 `MusicDiscovery` 没有 `toolNotes` 时可以读取。
- 新发现卡可以保存并重新读取工具观察记录。
- 作品地图筛选只显示匹配内容。
- 听觉实验室保留旧挑战入口。
- `npm test`、`npm run lint`、`npm run build` 通过。

### 桌面端人工验收

在宽屏桌面视口完成以下流程：

1. 从作品地图筛选并打开茉莉花。
2. 完成第一阶段先听和主观表达。
3. 从证据阶段打开音乐显微镜。
4. 比较片段并保存一个旋律观察。
5. 打开乐器探秘台并比较至少两个音色样本。
6. 打开节奏与动作工作台，完成一次稳定拍跟随。
7. 打开文化换镜，带着文化信息再听。
8. 返回探索剧场并保存包含工具证据的发现卡。
9. 从听觉实验室自由打开工具，确认仍可返回作品。
10. 打开旧挑战入口，确认原有训练流程仍可使用。

本阶段不进行手机和平板视觉验收。

## 11. 分阶段交付建议

### 2A：数据边界与音乐显微镜

- 扩展探索单元和发现卡可选字段。
- 完成音乐显微镜。
- 只接入茉莉花。
- 验证工具观察能进入发现卡。

### 2B：作品地图与听觉实验室

- 将 CourseCenter 重构为桌面作品地图。
- 将 TrainingCenter 顶部重构为听觉实验室。
- 保留旧课程和挑战入口。

### 2C：乐器探秘台、节奏工作台与文化换镜

- 完成两个新增工具。
- 接入文化信息和二次聆听。
- 完成三工具之间的统一返回和发现卡记录。

## 12. 风险与取舍

### 音色真实性

合成音色适合交互原型和比较，但不能代表真实乐器的全部文化和演奏特征。界面要明确“声音样本”，后续可以替换为授权录音而不改变工具接口。

### 工具过多导致注意力分散

每个作品只推荐一到两个工具，其他工具放在听觉实验室，不在探索主流程全部展开。

### 旧页面和新页面并存

本阶段不强行删除旧入口，而是将旧入口降为支持或更多练习，减少回归风险。

### 数据扩展兼容

新增字段全部可选，读取时对异常数据做边界限制，保存失败不阻塞学生完成探索。

## 13. 明确决策

- 本阶段目标平台固定为桌面端。
- 推荐采用渐进式重构，不创建第二套并行导航系统。
- 新工具以证据和回听为中心，不以分数为中心。
- 第一版使用现有音频引擎和可替换的合成音色。
- 只将一到两个工具推荐给单个作品，其余工具放在听觉实验室。
- 旧训练、理论、器乐页面继续保留，并通过桌面端新入口重新组织。
