# 音乐探索剧场：学生音乐欣赏体验重构设计规格

## 2. 产品定位

将产品从“音乐工具与知识功能集合”重构为面向浙江省小学 1—6 年级课堂的“音乐探索空间”。

学生不是先阅读乐理、再回答知识题，而是先遇见一段音乐，形成自己的感受，再通过行动、比较和回听寻找音乐依据，最后在需要的时候学会一个能够解释声音的概念。

核心学习目标从“记住知识点”转为：

> 我听到了什么？
>
> 我有什么感受？
>
> 我是从音乐的哪里听出来的？

产品的核心结果不是唯一的审美答案，而是学生逐渐能够把“我觉得”说成“我是从音乐中听出来的”。

## 3. 设计依据与核心原则

### 3.1 四条进入音乐的路径

情绪、动作、故事、文化不是四个固定栏目，也不是四个必须依次完成的活动，而是学生进入同一段音乐的四种认知路径：

| 路径 | 核心问题 | 常见音乐证据 |
| --- | --- | --- |
| 情绪 | 我感受到了什么？ | 速度、力度、节奏、音色、旋律、织体 |
| 动作 | 音乐如何驱动我的行动？ | 稳定拍、重音、乐句、停顿、变化 |
| 故事 | 音乐让我看见了什么？ | 速度、力度、音色、旋律、结构变化 |
| 文化 | 知道背景以后，我重新听到了什么？ | 节奏、旋律、音色、调式、结构、音乐功能 |

每个探索单元根据作品特点选择一到两条主路径，其他路径作为可选表达方式，不强行堆叠。

### 3.2 音乐证据闭环

所有路径最终都回到同一条学习链：

```text
听到音乐事实 → 产生主观感受 → 做出行动或想象 → 寻找音乐依据 → 再听验证 → 调整理解
```

产品中的关键追问统一为：

> “你是从音乐的哪里听出来的？”

这条追问用于防止四种体验滑向错误方向：情绪变成猜形容词，动作变成教舞蹈，故事变成教师讲答案，文化变成背景知识背诵。

### 3.3 乐理知识的角色

乐理不再是学生进入作品前必须阅读的课程目录，而是解释已经听到现象的“音乐线索卡”。

新的顺序是：

```text
先听到现象 → 做出判断 → 互动验证 → 学会概念 → 带着概念再次聆听
```

知识卡应短、可听、可比较、可回到作品验证。完整定义、历史背景和拓展内容放入可展开区域，避免占据主流程。

### 3.4 审美表达不以唯一答案评分

学生可以有不同的情绪、动作、故事和文化联想。系统不把主观偏好直接判为对错，也不以标准答案覆盖学生表达。

反馈关注三件事：

- 学生是否注意到可听见的音乐事实。
- 学生能否把感受与音乐事实建立联系。
- 学生第二次聆听后是否发现、补充或修正了新的线索。

## 4. 统一探索单元模型

每个作品、器乐主题或音乐现象都应能够描述为一个可复用的探索单元，而不是一个知识章节。

### 4.1 学生体验流程

```text
1. 先听
2. 说感受
3. 做猜想
4. 找证据
5. 知识浮现
6. 再次聆听
7. 形成“我的音乐发现”
```

#### 先听

播放 15—40 秒的核心片段，提供播放、暂停和重听。首次聆听不提前给出“热烈”“五声音阶”“某某乐器”等结论，只提供开放但具体的听觉提示。

#### 说感受

根据年级提供表情、情绪、动作、颜色、画面、故事和短句等表达方式。低年级以选择和拖拽为主，高年级逐步增加自由表达。

#### 做猜想

系统不立即公布答案，而是邀请学生预测：音乐可能因为什么产生这样的感觉？选项应围绕可听证据，例如“快慢”“强弱”“节奏”“声音的样子”“旋律走向”。

#### 找证据

每个单元只安排一到两个最有帮助的互动：

- A/B 片段比较。
- 找出音乐变化发生的时刻。
- 主要乐器或音色辨认。
- 节奏、重音或稳定拍跟随。
- 旋律上行、下行、重复或呼应的图形表达。
- 旋律、伴奏、打击乐等层次的试听。

互动不追求数量，而追求是否帮助学生回答“为什么这样听到”。

#### 知识浮现

知识卡只解释当前已经听到的现象，例如：

```text
你刚才听到的是：力度

力度就是声音的强弱。
声音变强，音乐会更有力量；
声音变弱，音乐会更轻柔。

再听一次，注意音乐什么时候变强。
```

每张卡至少包含一个声音示例、一个视觉变化、一句儿童可理解的解释和一个回听任务。

#### 再次聆听

学生带着新概念回到同一片段，可以保留原感受、补充音乐证据、修改故事或标记第一次没有注意到的地方。

#### 我的音乐发现

结束时形成一张可保存、可回看、可供教师观察的发现卡：

- 作品与片段。
- 我的感受。
- 我的动作、画面或故事。
- 我听到的音乐证据。
- 我今天发现的音乐词语。
- 再听后我的新发现。

### 4.2 探索单元的内容结构

探索单元应至少包含以下概念层级：

```text
作品
  ├─ 年级适配
  ├─ 教材与浙江课程映射
  ├─ 主路径：情绪 / 动作 / 故事 / 文化
  ├─ 核心片段
  ├─ 首次聆听提示
  ├─ 主观表达选项
  ├─ 音乐证据互动
  ├─ 音乐线索卡
  ├─ 二次聆听提示
  └─ 发现卡总结模板
```

一个单元可以对应多个年级版本，但不应复制成六套完全独立的内容。差异主要体现在支架、提示、互动复杂度、术语深度和表达自由度。

## 5. 年级适配策略

### 1—2 年级：先感受，再模仿

- 主要表达：表情、颜色、简单动作、画面选择。
- 主要证据：快慢、强弱、声音高低、声音是否相同。
- 互动形式：大按钮、跟随、模仿、简单 A/B 选择。
- 总结形式：图标 + 一句话或口头表达。

引导示例：

> “它像开心地跳，还是安静地走？”
>
> “哪里听起来更有力量？”

### 3—4 年级：比较、辨认、说明

- 主要表达：情绪、动作、画面、简短理由。
- 主要证据：速度、力度、节奏、主要乐器、旋律重复和呼应。
- 互动形式：片段比较、乐器辨认、节奏跟随、变化定位。
- 总结形式：“因为……所以……”句式。

引导示例：

> “哪一段更像在奔跑？你听到了速度还是节奏的变化？”

### 5—6 年级：判断、解释、再创造

- 主要表达：完整观点、故事设想、文化联想和修正理由。
- 主要证据：旋律、织体、结构、调式、配器、音乐功能和文化语境。
- 互动形式：层次试听、结构标记、调式或音阶比较、文化前后回听。
- 总结形式：“判断—证据—理由—回听变化”。

引导示例：

> “哪个音乐事实支持你的判断？”
>
> “知道这段音乐的地域背景后，你第二次听到了什么？”

## 6. 第一阶段试点：茉莉花

### 6.1 单元定位

试点作品：`《茉莉花》/《茉莉花开（民乐）》`

试点主题：

> “一朵花，为什么能唱出江南的味道？”

选择依据：

- 项目现有曲库和百科已有相关内容，可优先复用。
- 旋律短小，适合低年级先感受和模仿。
- 可自然观察旋律走向、音色、级进、五声音阶和地域风格。
- 同时具备情绪、故事、动作和文化入口。
- 能验证“第一次感受—寻找依据—文化进入—再次聆听”的完整闭环。

### 6.2 三个年级版本

#### 1—2 年级版本

主题问题：这段音乐像什么？

学生先听片段，选择“花朵开放”“小河流动”“轻轻走来”等画面或动作，再关注轻柔/有力量、快/慢、平稳/跳跃等听觉线索。

知识浮现以“旋律走得平稳”“声音有自己的颜色”为主，避免一次引入五声音阶等抽象术语。

#### 3—4 年级版本

主题问题：为什么听起来很婉转？

通过级进与跳跃的对比、不同乐器音色辨认和旋律片段比较，引导学生观察旋律如何流动、声音如何塑造气质。

知识浮现包括旋律、级进、音色，并要求学生用“因为……所以……”表达依据。

#### 5—6 年级版本

主题问题：为什么它有“中国风味”？

通过听辨所用音、比较旋律材料、了解江苏等不同地域版本，引出五声音阶、主音感、民歌地域变化和文化语境。

文化信息必须放在初次聆听和问题产生之后，并在文化信息进入后再次回到音乐。

### 6.3 试点验收体验

一个学生完成试点后，应至少能够：

- 说出一个自己的主观感受或画面。
- 完成至少一次基于声音的互动判断。
- 指出一个支持自己感受的音乐证据。
- 学会一个与本次聆听直接相关的音乐词语。
- 进行第二次聆听并补充或修正自己的发现。
- 保存一张属于自己的“音乐发现卡”。

系统不要求所有学生得出相同的情绪答案，但应能够看见他们是否从感受逐步回到了音乐证据。

## 7. 信息架构迁移

### 学生端主入口

学生端逐步收敛为四个主入口：

1. **今日探索**：推荐一段适合当前年级和课堂进度的探索。
2. **作品地图**：按年级、教材单元、器乐、浙江文化主题和路径浏览。
3. **听觉实验室**：集中放置听辨、比较、节奏、乐器和声音实验工具。
4. **我的发现**：查看感受、证据、故事、文化理解和回听变化。

### 现有页面迁移

| 现有页面或模块 | 新定位 | 迁移原则 |
| --- | --- | --- |
| `Home` | 今日探索 | 从功能分发改为作品探索推荐和继续探索 |
| `LessonMode` | 探索剧场 | 承载完整探索单元状态机 |
| `MusicExperienceStage` | 通用探索舞台 | 承载路径入口、音频互动、证据反馈和回听 |
| `CourseCenter` | 作品探索地图 | 以作品和主题组织教材，不以知识章节为主 |
| `Theory` | 音乐线索库 | 将乐理内容拆成短卡片，支持按现象查找 |
| `TrainingCenter` | 听觉实验室 | 将游戏重新解释为探索中的听辨工具 |
| `Library` | 音乐与文化资料库 | 承载作品、乐器、地方音乐和可展开背景 |
| `AdventureMap` | 我的发现 | 展示发现卡和个人探索路径 |
| 钢琴、鼓、木琴、竖笛 | 声音实验工具 | 作为探索中的试听、模仿和创作工具保留 |
| 各类音乐游戏 | 探索任务 | 从孤立入口逐步嵌入作品学习流程 |
| `Dashboard` | 教师课堂观察 | 从分数统计扩展到感受、证据、表达和回听变化 |

### 迁移顺序

第一阶段只验证完整体验链：`Home`、`LessonMode`、`MusicExperienceStage`、发现记录和茉莉花试点。

第二阶段接入现有听音、节奏和乐器工具，并将 `CourseCenter` 调整为作品地图。

第三阶段拆分理论内容、重做“我的发现”和教师课堂观察。

第四阶段扩充春节序曲、江南丝竹、越剧、梁祝、龙舟节奏等内容。

## 8. 技术边界与兼容策略

### 8.1 保留的基础能力

- React 18 + TypeScript + Vite。
- 现有 Tone.js 和 Web Audio 音频能力。
- 单文件构建和离线优先。
- 浏览器 `localStorage` 本地数据模式。
- 现有学生、年级、学期和课堂管理能力。
- 现有音频引擎、乐器互动和可复用 UI 组件，除非试点验证后明确需要替换。

### 8.2 数据策略

采用增量扩展，不破坏现有进度、发现和备份数据。

现有 `MusicDiscovery` 只有标题、陈述和标签，后续应扩展为能够兼容以下信息的记录：

- 体验单元与作品。
- 学生首次感受。
- 选择的路径。
- 音乐证据。
- 浮现的音乐线索。
- 二次聆听后的新发现。
- 年级和教材映射。

旧记录仍然可以以简化发现卡显示，不要求补齐历史字段。新字段应采用可选字段和版本兼容读取，避免已有本地数据失效。

### 8.3 探索流程状态

探索剧场需要有明确、可恢复的流程状态：

```text
idle → listening → expressing → hypothesizing → finding-evidence
     → concept-reveal → relistening → reflection → completed
```

学生中途退出后可以继续上次单元，但每一步都应允许重听，不能因为跳过一次互动而永久卡住。

### 8.4 音频策略

第一阶段优先使用项目已有的离线音频、合成音和片段能力，不引入后端和外部音频服务。真实录音素材如需加入，应先明确版权、离线打包和备份策略。

## 9. 反馈与评价设计

### 对学生

反馈用观察性语言，不把主观感受标成错误：

- “你注意到了后半段的鼓点变密。”
- “你把‘热烈’和‘速度变快’联系起来了。”
- “这次你发现了第一次没有注意到的音色变化。”
- “你的画面和另一位同学不同，但你找到了音乐里的依据。”

答错的证据判断也应鼓励再听和比较，而不是只显示红色错误：

> “再听一次两个片段，注意哪一个的重音更明显。”

### 对教师

教师观察从单一分数扩展为：

- 学生是否完成首次感受表达。
- 学生常选择的路径。
- 学生能否指出速度、力度、节奏、音色等证据。
- 学生是否完成二次聆听。
- 学生是否修改或补充发现。
- 班级对同一作品的不同理解分布。

这些信息用于课堂反馈和下一次引导，不用于给审美偏好排名。

## 10. 明确不做的事情

第一阶段不做：

- 一次性重写所有课程和百科内容。
- 删除现有理论页、游戏页和乐器页。
- 引入复杂 AI 情绪识别或自动判断学生审美是否正确。
- 引入排行榜、班级竞争、货币和复杂养成。
- 引入后端、账号体系或强依赖在线资源。
- 用大量文字替换现有大量文字。
- 要求每个作品都完整覆盖四条路径。

## 11. 设计成功标准

第一阶段成功不以页面数量衡量，而以首个探索闭环是否成立衡量：

1. 学生能在没有先读长篇理论的情况下开始聆听。
2. 学生能表达自己的感受、动作或画面。
3. 系统能把表达引回可听见的音乐证据。
4. 互动能帮助学生发现至少一个音乐现象。
5. 乐理概念在发现之后出现，并能立即回到片段验证。
6. 二次聆听能产生补充、修正或更具体的表达。
7. 学生能保存可回看的音乐发现卡。
8. 教师能看到过程性信息，而不仅是答题分数。
9. 现有本地数据、单文件构建和离线播放能力不被破坏。

## 12. 后续步骤

设计规格通过审阅后，下一步使用 Superpowers 的 `writing-plans` 流程，生成第一阶段实施计划。实施计划需要进一步明确：

- 探索剧场的组件边界。
- 第一阶段状态与数据类型。
- 茉莉花试点的实际内容配置。
- 现有 `MusicExperienceStage`、`experienceActivities`、`discoveries` 的兼容改造方式。
- 页面迁移和旧入口保留策略。
- 单元测试、构建验证和浏览器交互验收。

在实施计划和用户再次确认之前，不开始应用代码改造。
