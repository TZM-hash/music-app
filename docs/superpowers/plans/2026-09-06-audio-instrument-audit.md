# 音频、乐器与桌面端功能审计实施计划

## 目标

修复音乐探索馆候选试听音色错误、森林游戏节奏回放失效，并建立可用于直接打开 `乐动课堂.html` 的音频资源层；扩展左侧乐器入口，逐项审计电脑端核心页面与小游戏，最终构建、同步单文件、提交并推送 `master`。

## 边界与约束

- 只修改电脑端行为与桌面端布局，不处理手机和平板。
- 不删除已有阶段功能、旧小游戏、课堂入口或森林游戏。
- 不使用子代理；按任务顺序在当前工作区实施。
- 不纳入用户已有未跟踪目录 `旧版本/`。

## 执行步骤

### 1. 资源层与单文件路径

- 盘点 `public/reference-courseware`、钢琴采样及当前 `referenceAssets` 的引用。
- 将现有参考音频以源码 import 方式接入，保留可读的资源元数据。
- 增加播放失败时的指定乐器合成兜底，并统一停止旧播放的边界。
- 增加资源层单元/源码测试，先验证旧根路径不会继续作为单文件必需条件。

### 2. 音乐探索馆试听

- 为木鱼、碰钟、钢琴候选绑定不同的资源或 `InstrumentId`。
- 先写失败测试，再实现真实音频优先和不同音色兜底。
- 验证 A/B 选择、听感反馈与文化线索不被破坏。

### 3. 森林游戏节奏回放

- 为 pattern 回放写失败测试：顺序、休止符、空输入、重复点击、卸载清理。
- 实现可取消的 timer/播放 token，并在完成后更新反馈。
- 运行定向测试与开发页交互验证。

### 4. 乐器侧栏与共用试听页

- 建立数据驱动的实际乐器清单和共用桌面试听页。
- 更新 route union、导航标签、App 分发、学生导航和侧栏分组/滚动。
- 为新增入口提供不同的可辨识合成音色；有真实素材时优先使用真实素材。
- 验证所有入口可进入、可返回、可试听。

### 5. 其他电脑端功能审计

- 检查音乐探索馆、互动课堂、音乐显微镜、乐器探秘台、节奏与动作工作台、森林游戏、音符/节奏/跟唱/读谱/太鼓小游戏、作品与素材、选曲、混音及已有乐器页。
- 对发现的播放不触发、切页残留、按钮无反馈、资源加载失败问题做最小修复，并为每个修复补定向测试。
- 保留与本轮音频审计无关的用户现有改动。

### 6. 构建与单文件验收

- 运行 `npm test`、`npm run lint`、`npm run build` 及本次文件的格式检查。
- 用构建产物覆盖根目录 `乐动课堂.html`，确认单文件包含导入音频资源。
- 直接以 `file://` 打开并检查核心入口、候选试听、节奏回放、森林游戏、所有乐器入口、作品试听和旧小游戏的进入/返回/重试。
- 复查 `git diff`，确保没有把 `旧版本/` 加入 Git。

### 7. 提交与推送

- 在 `master` 上提交源码、测试、文档与同步后的 `乐动课堂.html`。
- 使用用户已配置的代理推送 `origin master`。
- 推送后再次检查分支状态与最新提交，向用户报告验证证据和仍需人工感知的音频差异。

## 验证命令

```powershell
npm test
npm run lint
npm run build
npm run format:check
```

提交前还需确认：`git status --short --branch`、`git log -1 --oneline`，并确保工作树只剩用户已有的 `旧版本/` 未跟踪目录（若构建生成临时文件则清理或忽略）。
